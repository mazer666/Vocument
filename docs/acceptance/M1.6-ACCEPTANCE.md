## 1. Starting point

The task was to close the gaps in the evidence from M1.4b/M1.5. The previous
acceptance records served as the basis. An **independent audit** of the six
commits examined them and **refuted four claims or exposed them as
incomplete**:

| # | Finding | Severity |
|---|---|---|
| 1 | The native library integration would have **prevented the application from starting** on a device: `DT_NEEDED` demanded `libmupdf.so.28.5`, the packaging only captures `*.so` | Critical |
| 2 | All native libraries were aligned to **4 KB**, not 16 KB compatible | Critical |
| 3 | `shutdown()` **never** signalled running jobs, although the doc comment claimed it did | High |
| 4 | The **PDF viewing path blocked the UI thread** (viewport rendering, prefetch, thumbnails) | High |

These findings are fixed in M1.6. The old records remain unchanged as
historical evidence.

### 3.5a Release package — PASS (was NOT RUN)

The release build ran through with the profile-aware native build:

```text
BUILD SUCCESSFUL in 6m 55s
48 actionable tasks: 8 executed, 40 up-to-date
```

Result: **95 MB** (previously 196 MB). The check of the package:

```text
Native libraries packaged in app-release-unsigned.apk:
--- ABI arm64-v8a
  - libleptonica.so (3.5M)
  - libmupdf.so (56M)
  - libtesseract.so (3.4M)
  - libvocument_ffi.so (4.7M)
✓ Native library closure resolves and every library is 16 KB page compatible.
```

`libvocument_ffi.so` fell from 102 MB (debug) to **4.7 MB** (release, stripped).

**Size analysis of the release package (95 MB, 98 MB uncompressed):**

| Share | Size | Note |
|---|---|---|
| `lib/` | 67.2 MB | of which `libmupdf.so` 58 MB — **unstripped** |
| `classes.dex` + `classes2.dex` | 20.8 MB | two DEX files |
| `assets/` | 5.6 MB | `eng.traineddata` 4.1 MB, `deu.traineddata` 1.5 MB |
| `res/`, `resources.arsc` | 0.9 MB | |

**Finding and measure:** the Rust library was stripped, the engine libraries
were not. `libmupdf.so` therefore carried around 35 MB of symbol information in
the package. The native build now removes the debug information in the release
profile from the engine libraries as well.

### 3.5b Difficult PDFs — PASS

Eight files that really occur: a damaged cross-reference table, a truncated
file, a page without an area, a page with 20000 × 20000 points, a cyclic page
tree, a missing content object, an encrypted file and a document with 200
pages.

| File | Behaviour of the engine |
|---|---|
| `damaged_xref.pdf` | repaired (`trying to repair broken xref`) |
| `truncated_stream.pdf` | reports cleanly (`format error: cannot find startxref`) |
| `zero_size_page.pdf` | opened |
| `huge_page.pdf` | opened, rendered |
| `cyclic_page_tree.pdf` | opened, terminates |
| `missing_content_object.pdf` | opened, content error reported |
| `many_pages.pdf` | 200 pages opened |
| `encrypted.pdf` | opened with an empty user password |

**Memory measurement** (peak resident size of the test process from the
kernel): 5.9 MB → **8.3 MB** for the entire corpus, including rendering.

**Memory error check with valgrind:**

```text
test result: ok. 14 passed; 0 failed
definitely lost: 0 bytes in 0 blocks
indirectly lost: 0 bytes in 0 blocks
ERROR SUMMARY: 0 errors from 0 contexts
```

**AddressSanitizer: NOT RUN.** The Rust sanitizer needs the nightly toolchain
(`-Zsanitizer=address` and `-Zbuild-std`); installed is the stable toolchain.
As a substitute valgrind memcheck serves, which detects the same class of
errors (invalid accesses, leaks) at runtime.

### 3.5 Package size — PASS

| Variant | Size | Note |
|---|---|---|
| Debug APK | 250 MB | contains 92 MB of DWARF debug information |
| Release APK | 23 MB (raw APK 196 MB **before** the profile correction) | After the profile correction: `Debug information removed: 101 MB -> 11 MB` |

**Limitation:** the content of the final release APK could **no longer be
verified**, because the execution environment failed during the last run. The
file exists; its composition is **NOT RUN**. The figure "release 23 MB" comes
from the run **before** the profile correction and is therefore to be treated
as a **pre-load**, not as a final value.

### 3.6 Job manager — PASS

* 20 tests in the core (`cargo test -p vocument-core --lib jobs::`), 0 failures.
* **Bounded shutdown:** `shutdown_grace_ms` (default 2 s) limits the waiting
  for the workers. A job body that ignores its token no longer blocks the
  shutdown — otherwise the `Drop` of the executor would have kept the process
  from exiting permanently.
* 5 end-to-end tests (`core/vocument-core/tests/job_manager_e2e_tests.rs`):
  the submission returns immediately, the job runs on another thread, the
  cancellation latency is bounded, the queue reports the overflow in a typed
  way, the closing of a session discards the late result, the status surface
  is readable during the run.
* Two mutation samples confirm the conclusiveness of the tests (see the audit).

### 3.7 Licensing — PASS (template), decision open

variants (AGPL conforming, commercial, alternative engine) with sources, risks
and a reasoned recommendation. **The decision is not made** and remains with
the project owner.

## 4. NOT RUN — with the concrete technical cause

| Item | Cause |
|---|---|
| On-device run of the APK | There is **no Android device** attached (`adb devices` shows no devices). |
| Emulator run | The emulator and the system image `android-34;google_apis;x86_64` could be installed, and the AVD `vocument_test` was created. The start without `/dev/kvm` (no `vmx`/`svm` in `/proc/cpuinfo`) takes place exclusively in software emulation; `adb` saw the device as `offline` during the boot. The boot status was undetermined when the execution environment failed. |
| macOS build and integration tests | There is **no macOS host**. The UniFFI Swift bindings are generated, but never compiled. |
| Responsiveness of the interface at runtime | Requires a device. The correction (A4 in the audit) is implemented and compiles, but is not measured. |
| Content of the final release APK | The execution environment failed during the check run. |
| Battery and thermal | No real hardware. |
| CI result | **No** workflow was executed. A CI result may not count as `PASS` without a run. |
| Android OCR on the device | The OCR path is not covered by the QEMU harness; Tesseract is built and in the package, it was not executed. |
| Energy and thermal behaviour on the device | Requires a device. The decision logic is fully checked on the host. |
| Responsiveness of the interface at runtime (capture **and** ingest path) | Requires a device. Both paths demonstrably run on the executor. |

## 6. Changed requirements

`REQUIREMENTS.md` receives in M1.6:

* **`ANDROID-16K-PAGES`** — Every delivered native library must be aligned to
  at least 16 KB memory pages.
* **`ANDROID-LINK-CLOSURE`** — Every `DT_NEEDED` entry must be resolvable by a
  file **with exactly that name** in the package.
* **`UI-001`** — Native work must not block the UI thread; that applies to
  **all** paths, not only to the scan path.
