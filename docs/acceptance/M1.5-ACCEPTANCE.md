## 1. Deliverables Checklist (`ROADMAP.md` M1.5)

| Deliverable | Implementation Location | Verification Status |
|---|---|---|
| **Central, platform independent `JobManager`** | `core/vocument-core/src/jobs/scheduler.rs`, `core/vocument-core/src/jobs/executor.rs` | **PASSED:** One implementation in the shared Rust core. macOS and Android use the same scheduler and the same worker pool; there is no second, divergent implementation. |
| **Bounded worker pool** | `core/vocument-core/src/jobs/executor.rs` | **PASSED:** The worker count and the queue length come from the central configuration (`config/performance-budgets.toml`, `[jobs]`). A submission beyond the queue bound fails with the typed error `JobError::QueueFull`. |
| **Job classes and priorities** | `core/vocument-core/src/jobs/scheduler.rs` | **PASSED:** Interactive, user-initiated and background classes, each with a base priority. |
| **Fairness / anti-starvation** | `core/vocument-core/src/jobs/scheduler.rs` | **PASSED:** A job that waits longer than `jobs.starvation_promotion_ms` is promoted by one priority level. Verified by the test `starved_background_job_is_promoted_over_newer_background_jobs`. |
| **Typed state machine** | `core/vocument-core/src/jobs/scheduler.rs`, `core/vocument-core/src/jobs/executor.rs` | **PASSED:** `Queued → Running → Completed | Failed | Cancelled`. A job cancelled while running can never report success; a job cancelled while queued never starts its body. |
| **Cancellation** | `core/vocument-core/src/jobs/scheduler.rs`, `core/vocument-core/src/jobs/executor.rs` | **PASSED:** Cooperative cancellation through a shared `CancellationToken`. No forceful thread termination anywhere. |
| **Progress and error reporting** | `core/vocument-core/src/jobs/executor.rs`, `platform/vocument-ffi/src/job_dto.rs` | **PASSED:** Progress and the terminal state are polled through the job status surface. The core never calls back into the UI. |
| **Real job payloads** | `platform/vocument-ffi/src/job_dto.rs` | **PASSED:** A submitted job performs a real core operation. A job kind without a core operation reports a `Failed` job instead of pretending to have succeeded. |
| **macOS integration** | `apps/macos/Sources/VocumentMacKit/DocumentCoreClient.swift` | **PASSED (code) / NOT RUN (build):** The Swift shell exposes the same core job manager. The Swift build cannot be executed in the current environment (no macOS host). |
| **Android integration** | `apps/android/app/src/main/java/org/vocument/app/ScanCaptureScreen.kt` | **PASSED (code) / NOT RUN (build):** The capture pipeline runs on a background executor; only the status strings are published to the Compose state. The Gradle build cannot be executed in the current environment (no Android SDK). |
| **Battery and thermal adaptation** | — | **NOT RUN:** `BIGMOBILE-001` / `POWER-001` are not implemented; they are listed in the milestone as still open. |

## 3. Defects found and fixed during this milestone

| Defect | Severity | Fix |
|---|---|---|
| `document_core_job_submit` always returned `Completed` without doing any work. The job manager therefore looked functional while executing nothing. | **Critical** | The job payload now performs a real core operation. A job kind without a core operation reports a `Failed` job with a description. Covered by `JOB-010` and by five integration tests. |
| `running_count()` always returned `0`: the counter was never incremented. | High | The worker increments the counter when a job starts and decrements it before the terminal state is published. Covered by `running_count_reflects_the_jobs_that_execute`. |
| The worker thread creation used `expect`, so a failure would panic instead of returning a typed error. A partially started pool would also have been returned. | High | `JobExecutor::start` returns `Result` and reports `JobError::WorkerSpawnFailed`; already started workers are stopped before the error is propagated. |
| The worker handle lock used `expect`, which would panic in the shutdown path. | Medium | The poisoned lock is recovered with `into_inner()`, so the worker threads are joined instead of leaking. |
| The queue used `expect` on a `Vec::remove` inside the worker loop. | Medium | The removal is handled as an error, so a future change of the container cannot turn into a panic inside a worker thread. |
| A cancellation request that arrived between the queue removal and the registration of the cancellation token could be lost: the job body would run to completion although it was already cancelled. | High | The token is signalled after the registration when the job was already marked as cancelled. Covered by `a_cancelled_job_never_reports_success_even_if_the_body_completes`. |
| `document_core_job_submit_placeholder` exposed a second submit function whose name suggested a stub. | Medium | The function was removed. |
| The interoperability gate failed on hosts with MuPDF in a custom prefix. (Pre-existing defect, also present on the baseline commit `91f83c3`.) | Medium | `interop_dto.rs` searches additional prefixes and sets `LD_LIBRARY_PATH` for the reference renderer. |
