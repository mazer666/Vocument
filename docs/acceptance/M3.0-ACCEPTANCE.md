## 1. Architectural Invariants Implemented

| Area | Implementation & Invariant | Status |
|---|---|---|
| **In-place Reorder** | Operates directly on the source `pdf_document` page tree. Invariant: flattens pages into self-contained nodes (inheriting `MediaBox`, `CropBox`, `Resources`, `Rotate` down to page dicts) while keeping Document Catalog, Metadata, Bookmarks, and Tagged structures byte-level coherent. | **PASS** |
| **In-place Duplicate** | Duplicates target page dictionary directly within the document without cross-document graft corruption. Invariant: deep-copies widget annotations and appends unique naming suffixes (e.g. `CustomerName_Copy1`) to `/AcroForm /Fields`, preventing form naming collisions. | **PASS** |
| **In-place Delete** | Deletes page entries in descending order. Invariant: removes deleted widget annotations from `/AcroForm /Fields` and safely re-anchors outline bookmark destinations targeting deleted pages to the nearest surviving page. Refuses emptying document (< 1 page). | **PASS** |
| **Non-destructive Extract** | Grafts requested pages into a standalone target document while preserving `/Info` and `/Metadata` XMP streams. Invariant: source document remains byte-for-byte unmodified. | **PASS** |
| **Digital Signature Preflight (`SIG-001`)** | Inspects active signatures before any structural mutation. Invariant: fail-closed by default with `OperationBlockedBySignature`. When explicit permission is granted (`allow_signature_invalidation = true`), existing signatures are marked as invalidated with notice and truncated byte range so viewers recognize invalidation. | **PASS** |
| **Transaction Integrity & Undo/Redo** | Implemented as first-class `TransactionCommand` variants (`ReorderPages`, `DuplicatePage`, `DeletePages`, `RestorePages`). Invariant: all state mutations flow through `DocumentActor`, support persistent journals, crash recovery, and reversible multi-step undo/redo. | **PASS** |
