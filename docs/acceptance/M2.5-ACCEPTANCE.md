## 1. Scope and Purpose of M2.5

M2.5 governs the legal, licensing, and supply-chain integrity required before any release candidate can be packaged or distributed. It establishes:

1. **Strict Copyleft & Licensing:** AGPL-3.0-or-later for the whole project (E1). No commercial MuPDF license dependency (E2). 100% free software, optional services only (E3).
2. **Offline-First Privacy Architecture:** Zero telemetry, no user tracking, no accounts, no cloud dependencies (E4, `NET-001`, `PRIVACY-001`).
3. **Technical Release Readiness:**
   - Deterministic and reproducible source archive packaging (`scripts/package-source-archive.sh`).
   - Binary build provenance tracking (`build_info.rs` with git commit SHA, dirty-tree refusal, and license identifiers).
   - 16 KB memory page alignment for Android 15+ native libraries.
   - Comprehensive third-party license inventory (`THIRD_PARTY.md`) checked against runtime dependencies.
   - Strict toolchain and license validation via `cargo-deny` (pinned version 0.20.2).
4. **Explicit Release vs Legal Demarcation:**
   - Technical readiness is decoupled from publishing authority.
   - Legal clearance (E5) cannot be granted by an agent; it belongs strictly to the project owner.
   - Mac App Store distribution is formally deferred (`docs/audit/apple-terms-verification.md`).
   - No public binary distribution occurs without explicit owner approval; source-only Alpha remains the documented foundation.

## 3. Resolution of RISK-059 (Android Transitive Dependencies)

During the initial licensing audits, inspection of the host Gradle cache (`~/.gradle/caches/modules-2/files-2.1`) revealed approximately 60 POM files with undeclared or unmapped licenses (including references to `io.netty` and `org.apache.httpcomponents`). This led to `RISK-059`.

**Resolution & Verification:**
- Gradle's dependency graph was audited via `./gradlew :app:dependencies --configuration releaseRuntimeClasspath`.
- The audit proved conclusively that `io.netty` and `org.apache.httpcomponents` are Gradle daemon/plugin dependencies (used by Android Gradle Plugin and build tools) and are **never** packaged into the release APK.
- The actual runtime APK dependencies consist strictly of:
  - `androidx.*` (all Apache-2.0, with `androidx.camera:camera-core` also noting BSD-3-Clause for `libyuv`)
  - `org.jetbrains.kotlin*` (Apache-2.0)
  - `com.google.auto.value:auto-value-annotations:1.6.3` (Apache-2.0)
  - `com.google.guava:listenablefuture:1.0` (Apache-2.0)
  - `net.java.dev.jna:jna:5.15.0` (Apache-2.0 OR LGPL-2.1-or-later)
- `scripts/audit-licenses.sh` validates all 12 shipped components against the Gradle cache with exit code 0.
- `RISK-059` is formally closed and marked **Mitigated** in `docs/project/RISKS.md`.

## 4. Operational Boundaries & Reserved Owner Authorities

The following aspects are explicitly documented as outside the scope of automated agent acceptance:

1. **E5 Legal Clearance:** Legal sign-off on public distribution contracts and third-party compliance remains solely with the project owner.
2. **Code Signing & Notarization:** Apple Developer ID signing certificates, Apple Notary service credentials, and Android production keystores are intentionally omitted from CI environments.
3. **Public Binary Distribution:** The project strictly remains in a source-only Alpha state until formal owner release commands are issued.
4. **Mac App Store Postponement:** The Mac App Store path remains deferred in favor of direct notarized distribution due to terms conflicts identified in `docs/audit/apple-terms-verification.md`.
