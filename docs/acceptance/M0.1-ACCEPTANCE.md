## 2. Technical

- Architecture boundaries respected: **yes** (`validate-repo.sh` enforces that `apps/macos` and `apps/android` contain zero direct MuPDF references; all PDF access goes through `vocument-ffi` → `vocument-core::SessionRegistry` → `PdfEngine` → `vocument-pdf-mupdf`)
- Central config respected: **yes** (`config/performance-budgets.toml` updated with `[code_limits]`)
- Source file size limits (`CODE-001`): **yes** (all hand-written files are $< 360$ lines; automated check in `validate-repo.sh` enforces target $\le 600$ / max $900$ lines)
- Tests green: **yes** (9 Rust unit/integration tests + Swift M0.1 session execution + Kotlin M0.1 SAF session execution)
- Migration/versioning checked: **yes**

## 3. Performance

| Metric | Budget | Measured | Result |
|---|---:|---:|---|
| Open PDF session + SHA-256 fingerprint + MuPDF metadata extraction | < 100 ms | < 10 ms on Apple Silicon | PASS |

Reference hardware/input: Apple Silicon (`arm64-apple-darwin`), `tests/corpus/m0_1_sample_two_pages.pdf` (2-page PDF 1.7, 697 bytes).

## 4. Usability

- task step count: macOS (`CalmReaderSessionView`) supports `onOpenURL` (Finder / Open With) and `NSOpenPanel` ("Open PDF…"); Android (`MinimalReaderSessionScreen`) uses `ActivityResultContracts.OpenDocument` (`application/pdf`) via Storage Access Framework.
- discoverability notes: Clear session summary displaying filename, page count, title/author, and SHA-256 fingerprint.

## 5. Accessibility

- keyboard & screen reader: Standard SwiftUI `GroupBox`/`Grid` and Jetpack Compose `Scaffold`/`Button` semantics.

## 6. Security/privacy

- new data stored: In-memory `SessionRegistry` only; closed sessions are immediately dropped.
- network access: None (`NET-001` strict offline).
- negative tests: Non-PDF bytes and missing files are cleanly rejected with typed errors (`InvalidPdf`, `FileBrokerFailure`); C `fz_try`/`fz_catch` prevents MuPDF exceptions from unwinding across Rust FFI.
- threat notes: Opaque `DocumentId` (`doc_1a00192b75fb403b`) and `SessionId` avoid leaking plaintext document names into internal IDs.

## 7. Interoperability/data integrity

- reopen in Vocument: Verified across both macOS and Android broker paths with identical SHA-256 (`1a00192b75fb403bf574c22afd1898a361e7f043d4f3489770c9560607370bee`) and metadata.

## 8. Known limitations

- Full interactive Android emulator/device UI execution of `ActivityResultContracts.OpenDocument` requires an Android SDK/device environment; locally, the exact `DocumentCoreBridge.openSafDocument(...)` code path and UniFFI/MuPDF session lifecycle are verified headlessly against `tests/corpus/m0_1_sample_two_pages.pdf` via `scripts/verify-kotlin-handshake.sh`.

## 9. Decision

**accepted** — M0.1 gate (*"No UI layer accesses MuPDF directly"*) and all M0.1 deliverables are satisfied; ready to proceed to **M0.2 — Rendering**.
