# Vocument — Final Report M1.4b / M1.5

**Date:** 2026-10-20
**Branch:** `feature/m1.5-job-manager-and-real-android-mupdf`
**Base:** `main` @ `91f83c3`
**Environment:** Linux, Rust 1.99.1, 2 CPUs, ~3 GB RAM, Android NDK r27c, qemu-user-static

---

## 1. Summary

Both main goals are implemented and **proven**:

1. **The Android MuPDF placeholder has been replaced by a real, reproducible MuPDF 1.28.5 cross build.**
   The file `engines/pdf-mupdf/csrc/mupdf_stub_bridge.c` is deleted. The Android
   library demonstrably links against `libmupdf.so.28.5` and `libtesseract.so`.
   The engine opens and renders a real PDF on ARM64 — proven by running it
   under `qemu-aarch64` and comparing the image pixel by pixel with the
   reference rendering of the host build.

2. **The job manager is real, shared and platform independent.**
   A common Rust core (`core/vocument-core/src/jobs/`) with a bounded worker
   pool, priority classes, fairness, a typed state model, cooperative
   cancellation, progress and lifecycle safety. macOS and Android use the
   **same** implementation. The submitted jobs perform **real** core
   operations.

**Additionally found and fixed:** a defect that already existed on the base
commit — the interoperability gate test failed on hosts with MuPDF in a custom
prefix.

## 4. Defects found and fixed

| # | Defect | Severity | Fix |
|---|---|---|---|
| 1 | `document_core_job_submit` always reported `Completed`, without doing any work | **Critical** | The job payload now performs a real core operation; without an operation → a `Failed` job. `JOB-010`. |
| 2 | `running_count()` always delivered `0` — the counter was never incremented | High | The worker increments/decrements correctly; test added. |
| 3 | `JobExecutor::start` used `expect` and delivered a partially started pool | High | `Result` + `JobError::WorkerSpawnFailed`; already started workers are stopped. |
| 4 | `expect` on the worker handle lock in the shutdown path | Medium | The poisoned lock is rescued via `into_inner()`, the threads are joined. |
| 5 | `expect` on `Vec::remove` in the worker loop | Medium | Error handling instead of a panic. |
| 6 | A cancellation between taking the job from the queue and registering the token could be lost | High | The token is signalled after the registration, if the job is already marked as cancelled. |
| 7 | `document_core_job_submit_placeholder` suggested a stub | Medium | Function removed. |
| 8 | `executor.rs` exceeded the hard limit of 900 lines | Medium | Tests moved to `jobs/executor/executor_tests.rs`. |
| 9 | `ScanCaptureScreen.kt` exceeded the target limit (639 lines) | Low | `ViewfinderOverlay` moved into its own file. |
| 10 | The interoperability gate failed on hosts with MuPDF in a custom prefix (**also present on `91f83c3`**) | Medium | `interop_dto.rs` searches further prefixes and sets `LD_LIBRARY_PATH`. |
| 11 | `prepare-android-mupdf.sh` used `libmupdf.so.1` instead of `libmupdf.so.28.5` | High | The version logic corrected. |
| 12 | The SHA-256 of the MuPDF archive was a placeholder value | High | The real value `98a5c10c…b7e934`, independently confirmed via Homebrew (`mupdf-tools`) and the FreeBSD ports; the check is now implemented. |
| 13 | `mutool` could not be linked for Android (`-lpthread`) | Medium | The build stops after the library; the installation is manual. |
| 14 | The cross build produced x86-64 objects (host linker) | High | The NDK `LD` explicitly, including `-m aarch64linux` for the embedded fonts. |

## 5. NOT RUN and BLOCKED — with the reason

| Item | Status | Reason |
|---|---|---|
| On-device verification (APK, camera, OCR) | **NOT RUN** | No Android device, no emulator, no Android SDK/Gradle available. The gate `scripts/verify-android-runtime.sh` is binding, but not executable here. |
| Android Gradle build (`assembleDebug`, `testDebugUnitTest`) | **NOT RUN** | No Android SDK. The native cross build for `aarch64-linux-android` **is** verified. |
| macOS Swift build and test | **NOT RUN** | No macOS host available. |
| Battery/thermal adaptation (`BIGMOBILE-001`, `POWER-001`) | **NOT RUN** | Not implemented; carried as open in `ROADMAP.md` M1.5. |
| Job pause/resume and job dependencies | **NOT RUN** | They require a task graph instead of a priority queue; carried as open. |
| Windows and Linux platform | **BLOCKED** | The order macOS → Android → Windows → Linux is binding. Android is implemented, but the macOS and the on-device verification are still outstanding. The planning is in `docs/cr/CR-0003-windows-and-linux-platform-support.md`. |
| MuPDF PKCS#7 / digital signatures on Android | **NOT IMPLEMENTED (documented)** | The Android NDK delivers no OpenSSL; the module is switched off with `HAVE_LIBCRYPTO=no`. Vocument does not implement digital signatures yet. Documented in `ADR-0017`. |
| AGPL source disclosure for the Android distribution | **OPEN** | The mechanism (in-app link, source archive, build bundle) is not decided. Captured as `RISK-009`; it has to be clarified before the first public Android release. |
| Growth of the APK size through `libmupdf.so` (~56 MB) | **ACCEPTED** | Captured as `RISK-010`; reducible later via unused formats and ABI splits. |

## 7. Recommendation

The Android side and the job manager side are implemented and proven on the
available state. Before the next milestone two things should be caught up:

1. **Get a device or an emulator.** The gates `verify-android-runtime.sh` (APK,
   camera, OCR) and the macOS build are the last open evidence items. They are
   binding, but not executable here — that is a question of the environment,
   not of the implementation.
2. **Evaluate the Windows/Linux CR** as soon as the macOS and the Android track
   are complete. The planning is in `CR-0003`; the order of the platforms is
   already written down there.
