# Vocument Risk Register

Tracked according to `PROJECT_MANAGEMENT.md` §9.

| ID | Description | Probability | Impact | Mitigation | Owner Role | Status |
|---|---|---|---|---|---|---|
| `RISK-001` | Concurrent access to mutable MuPDF state across threads causes crashes or memory corruption | Medium | Critical (S4) | Enforce serialized `DocumentActor` per session; only immutable display-lists/tiles run on worker threads (`ARCHITECTURE.md` §7) | ROLE-04 (PDF/MuPDF) | Active |
| `RISK-002` | External file modification (Finder, iCloud, SAF provider) races with local save and causes silent data loss | Medium | Critical (S4) | Multi-signal file identity check before atomic replacement; mandatory conflict UI (`ARCHITECTURE.md` §14, §16) | ROLE-03 (Rust Core) | Active |
| `RISK-003` | Visual-only redaction leaves underlying text, OCR layer, or hidden objects extractable | Low | Critical (S4) | Two-stage redaction with mandatory independent reopen/search/extract verification (`ARCHITECTURE.md` §29) | ROLE-09 (Security) | Active |
| `RISK-004` | UniFFI boundary leaks engine internals or blocks future out-of-process worker isolation | Low | High (S3) | Restrict UniFFI surface to opaque handles, immutable DTOs, and `EngineTransport` abstraction (`ARCHITECTURE.md` §5, §37) | ROLE-02 (Architect) | Active |
| `RISK-005` | Large scan PDFs exhaust mobile RAM on Android | Medium | High (S3) | Adaptive tile cache with strict memory budgets (`config/performance-budgets.toml`) and OS memory-pressure eviction | ROLE-14 (Performance) | Active |
| `RISK-006` | The Android build must link a real MuPDF engine. The placeholder bridge was removed; MuPDF 1.28.5 is now cross-compiled for `aarch64-linux-android` with the NDK (`scripts/prepare-android-mupdf.sh`) | Low (residual) | Critical (S4) | The placeholder bridge is deleted from the tree, `scripts/validate-repo.sh` rejects any placeholder PDF engine, and `scripts/build-android-rust.sh` verifies that the produced library depends on `libmupdf` and not on a stub | ROLE-04 (PDF/MuPDF) | Mitigated |
| `RISK-007` | The job execution layer has a bounded worker pool, but job pause/resume, job dependencies and resumability across process restarts are not implemented; a task graph would be required (`ARCHITECTURE.md` §8.1) | Medium | High (S3) | Scope recorded in `ARCHITECTURE.md` §8.1 and `ROADMAP.md` M1.5; the current model satisfies `JOB-004` … `JOB-009` and is used by both platforms | ROLE-03 (Rust Core) | Active |
| `RISK-008` | Platform-specific differences could leak into the shared core as target-specific branches, which would make the planned Windows and Linux tracks expensive and risky | Medium | High (S3) | `PLATFORM-003` … `PLATFORM-005` in `REQUIREMENTS.md` and `CR-0003` require platform traits in the core and a platform-neutral FFI surface; the platform order is binding | ROLE-02 (Chief Architect) | Active |
| `RISK-009` | The AGPL requires the Android distribution to offer the corresponding source of the linked MuPDF. The mechanism (in-app link, source archive in the APK, or a build-time source bundle) is not yet decided | High | High (S3) | Recorded in `ADR-0017`; the MuPDF source revision is already pinned by the build script, so the source can be provided from the same revision. Must be settled before the first public Android release | ROLE-18 (Licensing) | Open |
| `RISK-010` | Linking the real MuPDF engine grows the Android APK by roughly 55 MB (`libmupdf.so` for the release build), which affects download size and update cost | High | Medium (S2) | Recorded in `ADR-0017`; the size can be reduced later by enabling MuPDF build options that drop the unused formats (XPS, CBZ, HTML/EPUB) and by shipping per-ABI splits | ROLE-16 (Supply Chain) | Open |
